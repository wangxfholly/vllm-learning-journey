## 这份学习计划解决什么问题

后端工程师转 AI，最大的坑不是"不懂模型"，而是**把模型当黑盒、停在调 API**。
这 30 天刻意反过来：从"把一个模型跑起来"开始，一路深挖到"为什么这么跑、怎么扛住高并发、怎么优化吞吐"，最终交付一个**工业级可用的推理服务 + 网关**。

**最终产出**：vLLM 多实例部署 + Golang gRPC 网关（负载均衡 / failover / 降级 / 服务发现 / 可观测性 / 混沌测试），外加一张覆盖 L1~L5 的推理优化知识地图。

## 进阶篇 · 知识深挖（附录）

完成 30 天主线后，继续往深水区挖的几块硬骨头：

- **vLLM 五层优化全景**：L1 调参 / L2 量化 / L3 调度 / L4 并行 / L5 改源码，哪层单卡可实操
- **L4 多卡并行**：TP（张量并行）/ PP（流水线并行）/ EP（专家并行）/ DP（数据并行）怎么切、为什么这么切
- **PD 分离**：Prefill / Decode 异构集群，KV Cache 跨集群搬运的四层优化，直连 vs KV Cache Pool
- **GPU vs NPU**：架构差异、CUDA 生态护城河、为什么大厂双轨并存
- **平台化思路**：从单卡 MVP 到工业级推理平台的能力地图

---

## 三条贯穿始终的工程价值观

1. **异步化 + 把慢操作藏在快路径背后** —— 流式先返回首 token，脏活后台干。
2. **解耦：核心逻辑固定，业务逻辑通过接口注入** —— 框架定骨架，钩子点交还控制权。
3. **分层屏蔽复杂度** —— 硬件异构、并行拓扑、KV Cache 搬运全被推理引擎层吸收，服务层只管调接口。
